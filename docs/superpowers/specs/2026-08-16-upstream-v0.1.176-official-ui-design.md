# Sub2API v0.1.176 Official UI Sync Design

## Goal

Rebuild `aiwelink-dev` as Sub2API `v0.1.176` with the official application UI, then retain only the AIWeLink changes required for registration attribution, release identity, and repository operations.

## Source Of Truth

- Application baseline: upstream tag `v0.1.176`, peeled commit `e803e3851c0a7e222cfadeafad7b8636ab959d11`.
- Integration base: latest `origin/aiwelink-dev` so the corrective PR contains the current branch history and can be merged normally.
- `origin/main` is an older production branch. It may be inspected for history, but no application tree is restored from it.

## Required Result

- Backend behavior comes from Sub2API `v0.1.176` unless a file is part of the explicit AIWeLink allowlist below.
- The authenticated shell, dashboard, admin console, styles, and themes come from Sub2API `v0.1.176`.
- The PR #21 workbench redesign and the PR #29 console overlay are absent.
- AIWeLink reports version `0.1.176-1` and upstream version `0.1.176`.
- Release tags use the exact form `v0.1.176-1`.

## AIWeLink Allowlist

### Registration And Referral

- Capture the growth/referral session at the public entry point.
- Encrypt and enqueue registration delivery without blocking external delivery in the signup request.
- Bind the outbox event to successful email registration.
- Preserve the `/api` referral redirect and its homepage fallback.
- Preserve the migration, configuration, deployment examples, worker wiring, and focused tests needed by this flow.

### Authentication Safety Needed By Registration

- Keep affiliate attribution in the server-owned OAuth pending session.
- Keep pending email registration secrets and refresh tokens out of persistent browser storage.
- Keep the shared token refresh coordinator and stale-session protections.
- Port these changes onto the official `v0.1.176` auth implementation; upstream behavior wins wherever the same concern is already implemented upstream.

### Version And Release Identity

- Keep the separate AIWeLink and upstream version metadata.
- Keep API/UI exposure of both versions and AIWeLink release comparison.
- Keep strict release tag validation and the existing protected release/image workflows.
- Preserve the GitHub homepage branding from PR #25 and the workflow/report documentation already merged into `aiwelink-dev`.

### Focused Security Fixes

- Keep narrowly scoped CodeQL fixes only when they are not already present in `v0.1.176` and do not replace newer upstream behavior.

## Explicit Exclusions

- No PR #21 `workbench-*` shell, dashboard, style, or theme changes.
- No PR #29 channel monitor, dashboard, Grok, pricing, billing, model mapping, audio, web search, or other broad backend overlay.
- No whole-tree restore from `origin/main`.
- No version-only patch that claims `0.1.176-1` while application code remains on `0.1.170`.

## Integration Method

1. Add a failing sync contract that detects the old version pair and workbench markers.
2. Restore `backend/` and `frontend/` from the exact upstream tag.
3. Reapply allowlisted files from the already integrated and tested PR #29 tree where they are compatible with `v0.1.176`.
4. Resolve overlapping files by preserving the upstream implementation and adding only the minimum AIWeLink behavior.
5. Retain current AIWeLink CI, deployment, README, and workflow documentation outside the application tree, then adjust only what the new application baseline requires.
6. Validate the final delta against `v0.1.176` by path and content before opening the PR.

## Verification

- Sync contract: correct version pair, exact tag naming, and no `workbench-*` application markers.
- Focused Go tests: growth registration middleware, referral route, auth registration binding, outbox/worker, OAuth pending affiliate flow, and retained security fixes.
- Focused frontend tests: auth secrets, token refresh, pending registration, OAuth callbacks, version badge/store.
- Frontend typecheck and a production build if the local toolchain supports the repository lockfile.
- `git diff --check` and a final allowlist audit against `v0.1.176`.
