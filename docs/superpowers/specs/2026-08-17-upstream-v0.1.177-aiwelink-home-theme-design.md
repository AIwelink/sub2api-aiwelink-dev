# Sub2API v0.1.177 AIWeLink 首页与主题同步设计

## 目标

将最新 `origin/aiwelink-dev` 增量同步到 Sub2API 官方 `v0.1.177`，继续以官方后端和控制台结构为主体，同时恢复已在 `origin/main` 投产过的 AIWeLink 应用首页与完整红/金双主题。

最终发布身份为：

- AIWeLink 版本：`0.1.177-1`
- Sub2API 上游版本：`0.1.177`
- 发布标签：`v0.1.177-1`

## 权威来源

- 集成基线：`origin/aiwelink-dev` 的 `187045f117a144dfd26c41b07638314925089493`，即已合并的 PR #34。
- 上游应用更新：annotated tag `v0.1.177`，peeled commit `073e92d17178a1ccdb0a27017f572f10c9c7ab62`。
- AIWeLink 首页和最终主题：`origin/main` 的 `a13429cf479482d995052617249f9384a76874d2`。
- README 品牌首页、注册、OAuth、安全、`GET /r/:code`、版本、CI 和发布逻辑：当前 `origin/aiwelink-dev`。

`origin/main` 只作为首页和主题语义的来源，不能整体 merge、cherry-pick 或覆盖文件。旧分支的应用基线是 `v0.1.170-1`，整树恢复会丢失后续上游功能。

## 集成架构

同步分为三个有明确边界的层次：

1. 将 `v0.1.177` 合入当前 `aiwelink-dev`，冲突优先采用上游业务实现，再补回现有 AIWeLink 注册、OAuth、referral、版本和发布契约。
2. 在 `v0.1.177` 的 `HomeView` 和语言包结构上，选择性移植 AIWeLink 默认首页；保留官方 `home_content`、URL 首页和 compact 首页分支。
3. 在 `v0.1.177` 的组件结构上，移植主题 token、语义前景色、图表 palette 和必要消费者 hunk；不复制旧控制台组件 blob，不改变官方布局和信息架构。

任何无法归入这三层 allowlist 的差异均不进入同步 PR。

## 上游同步与冲突策略

### 上游优先

- 后端业务逻辑、数据模型、接口、调度、计费、OpenAI 转发和新迁移默认采用 `v0.1.177`。
- AIWeLink 不为上游已经实现的能力另建平行逻辑。
- 冲突文件先理解 `v0.1.177` 的行为变化，再把 AIWeLink 的窄范围契约融合到新结构。

### 必须保留的 AIWeLink 能力

- growth registration、异步 outbox、OAuth 注册归因和相关安全修复。
- `GET /r/:code` 的邀请码校验、固定 HTTPS 跳转、主页 fallback、`no-store` 和 SPA bypass。
- AIWeLink 与 Sub2API 双版本展示、严格标签校验、release/image CI 契约。
- GitHub README 品牌首页和 Logo。
- 现有部署样例、合并流程文档和发布报告中仍有效的 AIWeLink 内容。

### 重点冲突文件

- `.github/workflows/backend-ci.yml`
- `.github/workflows/release.yml`
- `.github/workflows/security-scan.yml`
- `backend/cmd/server/VERSION`
- `backend/go.mod` 与 `backend/go.sum`
- `backend/internal/config/config.go`
- `backend/internal/service/openai_ws_forwarder_payload.go`
- `frontend/pnpm-lock.yaml`

这些文件不得简单选择整侧版本。工作流保留 AIWeLink 发布约束并吸收上游 action/toolchain 更新；Go 和 pnpm 依赖以 `v0.1.177` 为基础重新生成或采用合并后锁定结果；业务文件保留上游新逻辑，仅融合 AIWeLink 注册/referral hunk。

## 应用内 AIWeLink 首页

### 恢复范围

- `frontend/src/components/home/*.vue` 的九个首页组件。
- `frontend/src/composables/useHomepageIntro.ts`。
- `frontend/src/views/HomeView.vue` 默认首页分支中的 import 和渲染选择。
- `frontend/src/i18n/locales/en/landing.ts` 与 `zh/landing.ts` 的 `home.redesign` 文案。
- 首页组件、intro composable 和 `HomeView` 默认分支的专项测试。

### 保持上游行为

- 管理员配置 `home_content` 为 HTML 时，继续渲染官方自定义内容。
- `home_content` 为 URL 时，继续使用官方 iframe/跳转逻辑。
- compact 首页继续使用官方终端式 compact 页面。
- 不整体覆盖 `HomeView.vue` 或语言文件，只移植对应 hunk。

首页恢复后，`deploy/AIWELINK_GROWTH_REGISTRATION_CN.md` 中关于 referral 落地后播放 `HomepageIntro` 的说明重新与运行时一致。

## 红/金双主题

### 视觉契约

- 浅色主色：玫红 `#D21F4B`。
- 深色主色：金色 `#FFC247`。
- 深色表面使用中性黑层级，不恢复旧蓝黑/青色品牌。
- 恢复语义前景色、公共页面层次、登录/设置/管理页面配色、图表 palette，以及主按钮 sheen 和 selected-state glow。

### 主题基础范围

- `frontend/src/styles/theme.css`
- `frontend/src/styles/onboarding.css`
- `frontend/src/style.css`
- `frontend/src/main.ts`
- `frontend/tailwind.config.js`
- `frontend/src/composables/useThemePalette.ts`
- token、前景色、遗留品牌色、主题效果和 palette 专项测试。

### 消费者融合范围

只在仍需要语义色适配的官方 `v0.1.177` 组件中融合 class、CSS variable 或 chart color hunk。重点人工融合账号弹窗、`VersionBadge`、`AppHeader`、`SettingsView`、`KeyUsageView` 和图表组件，不复制 `origin/main` 的旧组件实现。

### 明确排除

- PR #21 merge `bd242809204d2943b4f78d8db612fd40e9af3142` 的所有 workbench 结构。
- `feature/workbench-ui-iteration` 的 dashboard data bands、管理/运维表面扁平化和列表/表格重组。
- `workbench-shell`、`workbench-content`、`workbench-header`、`workbench-sidebar` token 或 marker。
- sidebar 宽度、header 高度、shell offset、卡片/仪表盘结构的旧改版。
- 与主题无关的 `frontend/src/api/__tests__/admin.system.rollback.spec.ts`。

官方 `AppLayout`、`AppSidebar`、`Dashboard` 和其他控制台信息架构必须保持 `v0.1.177` 结构。

## 自动化合同

现有 `deploy/tests/upstream-sync-contract-test.sh` 扩展为本次同步合同：

- 要求 `VERSION=0.1.177-1` 和 `UPSTREAM_VERSION=0.1.177`。
- 只接受精确发布标签 `v0.1.177-1`。
- 要求官方布局 marker 继续存在。
- 拒绝 `workbench-*` marker 和 workbench visual contract。
- 要求 AIWeLink 默认首页、浅色玫红、深色金色和主题入口存在。

专项 Vue 测试覆盖首页分支、intro 生命周期、主题 token、语义前景色和图表 palette。Go 聚焦测试覆盖发生冲突的业务包，以及 registration、OAuth、referral、version 契约。完整跨平台矩阵交给 GitHub Actions，不在本地重复全量执行。
